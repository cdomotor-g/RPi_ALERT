Site survey

Leave this Pi at a site a repeater or base station might go — for a day or three, with or without a network — and see which stations it hears there and how strongly. Everything heard is kept on the card and goes to MegaNet as receptions when it is next on a network; MegaNet's Reception Map → Site surveys lays it beside what the network itself received.

MegaNet

This Pi is an ingest point: one MegaNet token covers every receiver plugged into it.

Or paste one an administrator made on MegaNet's Admin tab → Ingest tokens (it is shown once):

Location

Where the receivers are. Anything but a GPS fix is recorded in MegaNet as approximate.

RTL-SDR

Every RTL-SDR stick listens on these channels unless it has its own below. ALERT Binary is what the 151.5 MHz networks send; Enhanced iFLOWS is what an ERT-A2 set to it sends. One format per channel, on purpose.

One stick hears every channel in a stretch of the band about 1.9 MHz wide, all at once, and each is a receiver of its own in MegaNet. A new base station hears all four of MegaNet's channels — 151.5, 151.525, 151.95 and 152.4 — and keeps hearing them when only its frequency is changed. Put a format after a channel sent in another one: 152.4 EIF. The sample rate goes up by itself to hold them — more channels and a higher rate take more of the Pi.

Each stick

Give a stick channels of its own to hear networks — or formats — further apart than one stick can. A blank field is the setting above; none in More channels leaves a stick with only its own frequency. Sticks that share a serial number (most do) are told apart by the USB port they are in, so keep each in its port.

Serial devices

Quansheng radios, ERT-A2 receivers and GPS units are recognised from what they send. Set a port's type here only if it is not.

Audio

Plug a speaker into the audio jack (or use HDMI or a USB sound card) to hear each ALERT burst.

Remote management

This base station checks in with MegaNet's Base Stations tab once a minute — MegaNet never connects to it, and there is nothing here for anyone else to connect to. MegaNet's administrators see its health and, if you allow it, change its settings, restart it and install updates. Never from there: the ingest token, where readings go, the web page's password, SSH keys, or this choice — it is made here.

SSH access

Log in as alert with an SSH key on this list — the same user name on every RPi ALERT, and no password to forget or pass on. Each key is one person's: take it off the list when they move on. Keys come only from the SD card, sudo rpi-alert access add-key, or the GitHub accounts and MegaNet team keys you choose to accept — never from this page or from MegaNet's requests.

Adding a key — and getting in when nobody can
  • On the SD card: a line ssh_key = ssh-ed25519 AAAA… you@laptop in rpi-alert.conf on its bootfs drive (the set-up page writes it). The card's lines replace the ones before.
  • A team's GitHub accounts: ssh_github = name, name on the card — their public keys, fetched every hour.
  • Over SSH, with sudo: sudo rpi-alert access add-key "ssh-ed25519 AAAA… you@laptop"; rpi-alert access lists them.
  • Nobody can get in: put alert_password = … in rpi-alert.conf on the card, boot, and log in as alert at the console (or over SSH, if password login is on). It is wiped from the card once applied.

Software updates

Updates install over the network: no need to re-flash the SD card. Settings, the queue and the receiver ids are kept, and if a new version does not start, the one before it is put back.
